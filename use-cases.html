Real problems. Inspectable transformations.

Dennis is useful anywhere a change needs to be more than "something that happened to the files."

When a transformation matters, Dennis turns it into a deterministic, human-readable artifact that can be reviewed, shared, verified, reproduced and applied later.

Explore the Use Cases

Software Engineering

The obvious use case — and only the beginning. Dennis is designed for changes that would otherwise be difficult to review, reproduce or trust.

Large Refactors

Plan structured changes across large codebases before touching the files. Review the transformation and apply it only when you are ready.

The plan becomes a durable description of what the refactor was supposed to do.

Language & Framework Migrations

Framework and API migrations often involve thousands of small, repetitive changes.

Generate a deterministic plan once, inspect it, package it, and replay the same transformation across projects.

Git-Based Projects

Use Dennis alongside Git to transform tracked projects while keeping the transformation itself explicit and independently verifiable.

The source repository remains the source of the project; Dennis preserves the transformation that happened to it.

Security Patches

Security fixes can be distributed as signed DEX artifacts. Recipients can verify the artifact and inspect the transformation before applying it.

That makes the patch itself part of the evidence.

When the Change Itself Is Evidence

Some transformations are not merely implementation details. They need provenance, accountability or independent verification.

Audit Trails & Compliance

A DEX artifact can preserve the plan, metadata, lineage and optional cryptographic signatures associated with a transformation.

This creates a structured record of what changed, rather than relying on memory or an opaque deployment log.

Chain of Custody

Transformations can move between people, machines and organizations without losing their identity.

Lineage and signatures allow recipients to establish where an artifact came from and how it relates to previous transformations.

Forensic Traceability

When something changed months ago, the useful question is often not simply "what is different now?"

Dennis can preserve the transformation history so that the evolution of a project can be reconstructed and checked.

Independent Disclosure

DEX artifacts are portable. A transformation can therefore be shared independently of the platform that was used to create or distribute it.

Researchers, auditors and teams can exchange verifiable evidence without surrendering ownership of the artifact.

Beyond Source Code

The same principle applies whenever a document contains meaningful human content that needs to survive a transformation.

Localization & Internationalization

Extract meaningful strings into a dictionary, let a human edit the translations, and generate a deterministic plan describing exactly what will change.

Dennis regions can explicitly identify content that is intended for transformation while leaving everything else alone.

Documents & Office Files

A document can be treated as a transformation source rather than an opaque binary blob: extract meaningful text, preserve a dictionary, and produce a transformed document that another user can rehydrate and review.

The goal is the same: preserve both the content and the history of how that content was changed.

Explicit Content Regions

Users can mark text explicitly with Dennis regions such as [{#text to change#}].

Regions remove guesswork. If text is marked for transformation, Dennis treats the marked content as content — including embedded markup — rather than trying to reinterpret it.

Human-Edited Transformations

A recipient can rehydrate an artifact, edit the actual document, and then run Dennis again to discover what changed.

The resulting plan can be packaged for another person, preserving the transformation instead of merely shipping the final file.

Teams & Organizations

Dennis becomes particularly useful when the person who creates a transformation is not the person who applies it.

Team Transformations

Share DEX artifacts between developers and teams so that a transformation can be understood and reproduced beyond the machine where it was created.

Review Before Execution

Separate deciding what should happen from actually doing it. A plan can be reviewed by another developer, manager, auditor or customer before execution.

Portable Delivery

Send the transformation itself instead of sending a modified directory and asking everyone to trust the result.

The recipient receives something inspectable, portable and independently verifiable.

Hosted or Self-Hosted

The Forge can provide storage, discovery and collaboration, while the underlying DEX artifacts remain portable and usable with the Dennis CLI.

Don't Just Change It.

Preserve the transformation that changed it.

That is the difference between a file that happens to be different and a transformation that can be understood, verified and trusted.
